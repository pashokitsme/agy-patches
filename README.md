# agy-patches

Локальные бинарные патчи для `agy` и Antigravity на macOS arm64. Версии, SHA-256 и абсолютные offsets не зашиты в код: скрипты ищут характерные ARM64-инструкции и проверяют их семантику перед изменением.

Патчи убирают локальный отказ вида `this account is ineligible ... not currently available in your location`. OAuth, токены, выбор модели и сетевые запросы не подменяются. Исходные бинарники и учётные данные в репозиторий не входят.

## Один вызов

```bash
./patch
```

Исполняемый файл показывает состояние установленных CLI и GUI и предлагает пропатчить CLI, GUI или оба сразу. Enter выбирает всё доступное. Перед изменением создаётся резервная копия с timestamp в `~/.agy-patches/backups/`.

При выборе GUI скрипт предлагает завершить Antigravity, ждёт выхода, применяет патч, выполняет ad-hoc подпись и проверку `codesign`, затем предлагает снова запустить приложение. CLI подписывается и проверяется автоматически.

Только показать состояние без изменений:

```bash
./patch --check
```

## Как находится место патча

После входа клиент получает результат авторизации и сведения об аккаунте. Даже при действительном OAuth-токене локальный код может превратить ответ с неподходящим tier в отказ. CLI тогда не отправляет сообщение, а GUI показывает экран `ineligible`.

В проверенных сборках после обхода локального отказа выполнение продолжается по обычному пути, включая `OnboardUser`, `GetUserStatus` и запросы генерации. Серверные ответы не изменяются.

### CLI

Цель по умолчанию: `~/.local/bin/agy`.

Скрипт ищет последовательность:

```text
cbnz x1, error
cbz  x0, success
ldrb w2, [x0, #8]
tbnz w2, #0, success
```

Он декодирует относительные переходы и проверяет, что `cbz` и `tbnz` действительно ведут к одному `success`, а ветка ошибки отличается. Затем `tbnz` заменяется на вычисленный `b success`. Предшествующая проверка `cbnz x1` сохраняется, поэтому ошибки OAuth не игнорируются.

### GUI

Цель по умолчанию: `/Applications/Antigravity.app/Contents/Resources/bin/language_server`. `app.asar` и JavaScript интерфейса не изменяются.

Скрипт ищет последовательность:

```text
b.gt success
cbnz x0, rejection
success:
```

Первый переход должен вести к инструкции сразу после `cbnz`. Именно этот `cbnz`, соответствующий непустому `IneligibleTier.GetReasonMessage`, заменяется на `b success`. Ошибки получения конфигурации, `OnboardUser` и `GetUserStatus` обрабатываются другими ветками.

## Защита от неправильного патча

- Нулевое или множественное совпадение считается ошибкой: файл не изменяется.
- Недостаточно совпасть opcode: проверяются регистры, условия и относительные адреса переходов.
- Уже patched-файл распознаётся по безусловному переходу к тому же `success`; повторный запуск не перезаписывает бинарник.
- Перед записью создаётся резервная копия и проверяется побайтовое совпадение с источником.
- Изменяется новый файл, который атомарно заменяет цель через `os.replace`.

Это позволяет пытаться патчить новые версии без allowlist. Если компилятор изменил последовательность или распределение регистров, скрипт безопасно остановится — тогда нужно обновить шаблон по результатам анализа новой сборки.

Атомарная замена важна для подписанного Mach-O: macOS кэширует подпись по vnode, поэтому изменение существующего файла на месте может привести к `Code Signature Invalid` при следующем запуске.

## Ручной запуск

CLI:

```bash
uv run --no-project python cli/patch.py --check
uv run --no-project python cli/patch.py
codesign --force --sign - ~/.local/bin/agy
agy --model gemini-4-argon-medium -p 'Ответь ровно: OK.'
```

GUI после завершения Antigravity:

```bash
uv run --no-project python gui/patch.py --check
uv run --no-project python gui/patch.py
codesign --force --sign - --preserve-metadata=entitlements /Applications/Antigravity.app/Contents/Resources/bin/language_server
codesign --force --deep --sign - --preserve-metadata=entitlements /Applications/Antigravity.app
codesign --verify --deep --strict /Applications/Antigravity.app
open -a Antigravity
```

Проверка на копии без изменения установленного приложения:

```bash
uv run --no-project python gui/patch.py --target /полный/путь/к/копии/language_server
```

## Подпись GUI

Изменение `language_server` делает исходную подпись Google недействительной. Все вложенные компоненты приложения подписываются заново локальной ad-hoc подписью, entitlements сохраняются.

Hardened runtime не сохраняется: на проверенной macOS 15 он отклонял загрузку Electron Framework с ошибкой `mapping process and mapped file (non-platform) have different Team IDs` даже после перевода всех компонентов на ad-hoc. `--deep` нужен, чтобы основной процесс и фреймворки имели согласованную подпись. SIP и системные настройки безопасности не изменяются. Разрешения, привязанные macOS к подписи приложения, могут быть запрошены повторно.

## Проверка

Динамический поиск проверен на оригинальных и уже patched-бинарниках, на перенесённых instruction sequences и на двусмысленных файлах с двумя совпадениями. CLI после патча выполняет настоящий запрос к `gemini-4-argon-medium`.

Через REA выполнен полный сценарий GUI: исчез экран `ineligible`, выбрана `Gemini 4 Argon Medium`, отправлен запрос `Reply with exactly GUI_ARGON_OK and do not use tools.`, получен ответ `GUI_ARGON_OK`.

## Обновления и откат

`agy update` и обновление Antigravity перезаписывают соответствующий патч. После обновления снова запустите `./patch`. Если знакомая ветка не найдена однозначно, скрипт откажется изменять файл.

Для отката завершите приложение, восстановите нужный `.original` из `~/.agy-patches/backups/` новым файлом и повторите подписание. Это восстанавливает код, но не подпись Google: для полного восстановления исходных подписей всего приложения переустановите оригинальный Antigravity. Скрипт сохраняет только бинарники, а не весь `.app` и `_CodeSignature` вложенных компонентов.
